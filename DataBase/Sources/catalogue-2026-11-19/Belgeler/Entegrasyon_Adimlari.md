# Paket kontrolünden sonra entegrasyon sırası

Bu dosya uygulama talimatıdır; burada yazması işlemlerin yapıldığı anlamına gelmez. Bu teslim hazırlanırken veritabanı yazımı veya kod birleştirmesi yapılmadı.

1. Ekip, kullanılacak ortak dalı teyit etsin. İncelenen en yeni demo ucu feature/democontrol @ 5b79729'dur. Yeni kod ayrı UniversityDecisionHub_Guncel_2026-11-19 klasöründe bulunur; eski çalışan klasörün yerel yamaları korunur.
2. Hedef PostgreSQL sunucusu, portu ve UniversityDecisionHub veritabanı doğru mu salt okunur sorguyla kontrol edin. Her bilgisayarın sayısal kimlikleri değişebilir.
3. Hedefin tam yedeğini alın; yedek özel kalmalı, GitHub/veri paketine girmemeli. Uygulanacak şema değişikliğinden önce çalışan API'yi durdurun.
4. Güncel klasörde model kontrolü çalıştırın. Bu teslimde `dotnet ef migrations has-pending-model-changes --project Backend/UniversityDecisionHub.Api --no-build` sonucu model değişikliği olmadığını söyledi. Hedef migration uygulama durumu ayrı kontroldür.
5. Migration listesini doğru hedefte inceleyin. Yeni kod `20261116191117_AddReviewModeration` alanlarını kullanır. Bekliyorsa yedekten ve hedef kontrolünden sonra uygulanır. Bu teslimde ana PostgreSQL'e migration uygulanmadı.
6. `Kontroller/Katalog_Sayim_ve_Sema_On_Kontrol.sql` ve tam alan karşılaştırmasını çalıştırın. Yerel veritabanı daha önce 104/9346/12591 düzeyine getirilmişti. Bu teslimde dosyalarda düzeltilen 20 kredi alanı veritabanında hâlâ boştur. Doğrulanan tek fark bunlarsa `Kontroller/20_Kredi_Duzeltmesini_Uygula.sql` ayrı olarak uygulanacak, ardından alan karşılaştırması sıfır fark vermelidir. Bu teslim sırasında SQL uygulanmadı. Sayıların eşleşmesi tek başına alanların eşleştiğini kanıtlamaz. Bütün alanlar ve sayılar eşleşiyorsa tam katalog aktarımını tekrarlamak gerekmez.
7. Başka hedef boş/eskiyse yalnızca gerekli geçmiş alan düzeltmelerini, 82 ilişki düzeltmesini ve tam katalog aktarımını sırayla ele alın. Bu paketteki 82 ilişkilik SQL, önceki 62 alan düzeltmesinin yerine geçmez. Eski hedefte kaynak farkı varsa önce mevcut değer raporu hazırlanmalı; dosyaları rastgele çalıştırmayın. Güncel yerelde bunların hepsi uygulanmıştı.
8. JSON dosyası `Veri/catalog.ready.json`'dır. Doğrulama komutu: `dotnet run --project Backend/UniversityDecisionHub.Api --no-launch-profile -- validate-catalog "DOSYANIN_TAM_YOLU"`. Başarılı beklenen sayılar 9, 135, 456, 104, 9346, 12591'dir. Doğrulama veritabanına yazmaz.
9. Aktarım gerekiyorsa aynı dosyayla import-catalog komutu ayrıca uygulanır; validate-catalog sonucu aktarım kanıtı değildir. Aynı anahtarlar tekrar üretilmez, farklı mevcut alanlar otomatik güncellenmez. Mevcut değerler uyuşmuyorsa işlem durur; veri kaynağı incelenir.
10. Ekip onayı gerektiren kayıt/profil etiketi/çoklu kadro API konularını kod sahipleri çözsün. Eski profile.js dosyasını güncel ekip sürümünün üzerine kopyalamayın. Yeni sürümde profil altyapısı zaten vardır.
11. API'yi güncel klasörden başlatın, tarayıcıyı Ctrl+F5 ile yenileyin; doğru API adresini kullandığını doğrulayın. Kayıt/giriş → profil → program seçimi → kaydetme → yenileme → uygun ders → yorum → başka oturumda okuma → yeniden başlatma sonrası kalıcılık zinciri hedef PostgreSQL'de sınanmalı. Test verisi kullanılacaksa ana veriden ayrı geçici veritabanı tercih edilir; bu teslim böyle bir test yapmadı.
12. Yorum gizleme/silme yetkileri ve normal kullanıcının yasak işlemleri hedefte ayrıca doğrulanmalı. Yeni migration'ın varlığı, bu işlevlerin demoda denenmiş olduğu anlamına gelmez.
13. Yalnızca veriler, gerekli kaynak kanıtları ve onaylı kod değişiklikleri seçilerek commit/PR hazırlanır. `git add .` ile özel dosyalar veya obj/bin eklenmemeli. Anket hesapları beklemededir. Push/merge yapılmış sayılmıyor.
